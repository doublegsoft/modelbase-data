Modelbase Data Model Specification
==================================

## 数据访问（DAO）

对任意对象，无论是实体还是值体，数据访问操作都必须包括：

* 插入（insert）

  直接向持久化表插入数据。

* 更新（update）
  
  直接根据对象数据更新数据。

* 部分更新（updatePartial）

  只更新传入的对象中有值的字段。

* 删除（delete）

  直接删除一条实体数据。

* 查询（select）
  
  根据查询条件查询实体数据集合。

* 计数（selectCountOf）

  根据查询条件统计实体数据数量。

* 去重查询（selectDistinctOf）
   
  去重查询实体数据集合。

## 数据服务（TX）

数据访问层统一内部Query耦合。

### {entity}

实体对象的数据服务操作，包括：

* 保存（save）
  
  先判断标识属性是否有值，无值就生成一个，同时在有值的情况下也要判断是否已存在，如果已存在则更新，否则插入。注意，更新为部分更新，也就是值为空的属性不被更新。

* 读取（read）

  通过对象标识属性获取唯一对象的数据。

* 获取（get）

  通过对象非标识属性获取唯一对象的数据，如果存在多个，只返回第一个。

* 查找（find）
  
  通过任意对象属性查找对象的数据，返回所有匹配的对象。

### {entity + [value]}

实体对象的定义就已经包含了一个（或多个）类型为值域对象数组的属性。

实体对象（含有集合属性）的数据服务操作，包括：

* 保存（save）

  1. 保存实体本身
  2. 值体集合比原来的多的部分要插入
  3. 值体集合和原来一样的部分需要更新
  4. 值体集合比原来少的部分需要删除
  5. 值体集合在插入时，如果关联的另外的实体对象有数据，同时保存

* 读取（read）

  读取完整的实体复合对象，实体对象和值体集合。

* 查询（find）

  查询实体集合，主要针对实体对象的查询，但是同时也支持对值体集合衍生出来的聚合作用的属性。

### [entity]

实体集合，其数据服务操作本质上也是循环逐个处理单个实体对象，包括：

* 保存（save）

  循环处理每一个实体对象，具体参考{entity}的保存规范。


### {value}

值体对象的数据服务操作，如果值体对象中包含了实体对象为持久化，则需要先保存实体对象，再保存值体对象作为关联关系。

### [value]

值体集合，其数据服务操作本质上也是循环逐个处理单个值体对象，包括：

* 保存（save）

  循环处理每一个实体对象，具体参考{value}的保存规范。

### {meta} = {entity} + [value]

元型扩展对象，类似于{entity + [value]}，但是它的值体集合相对固定，不会轻易改变，并且值体对应的属性也是固定的。比如，在不改变某些实体对象表结构的情况下，在meta表上扩展实体对象的其他需要存储的属性。

行列转换扩展对象，类似于{entity + [value]}，但是它的值体集合相对固定，不会轻易改变。比如，医疗报告中的检验报告，一个报告主体，对应若干检验指标项的明细。

### {one-to-one} = {entity + entity}

直接关联对象，一个实体对象的标识是另一个实体对象，在数据库层面上就是两者的主键相同。

数据服务操作，包括：

* 保存（save）
 
  1. 通过定义的业务唯一字段，找到标识引用的其他实体，如果未定义着无此操作。
  2. 如果是插入操作，则标识对应的表和实体本身的表需要同时插入。
